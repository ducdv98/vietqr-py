# Internationalisation and theming

Library: next-intl. Default locale `vi`, also `en`. Which locales are offered is runtime
config (`VIETQR_LOCALES`, `VIETQR_DEFAULT_LOCALE`), not a build-time setting.

## How the locale is chosen

Cookie `NEXT_LOCALE` (set by the switcher), else `Accept-Language`, else the default.
Only enabled locales are honoured. There is no `/vi` URL prefix: prefix routing and
middleware matchers need the locale list at build time, which conflicts with runtime env
config. The switcher is hidden when only one locale is enabled.

## Messages

One JSON file per locale in `messages/` (`vi.json`, `en.json`), grouped by namespace
(`Nav`, `Footer`, `Shell`, `Home`, ...). `en.json` is the reference for keys.

- Server component: `const t = await getTranslations("Home")` (or `useTranslations` in sync components).
- Client component: `const t = useTranslations("Shell")`.
- ICU placeholders: `"Hello {name}"` then `t("key", { name })`.

`pnpm i18n:check` fails when any locale's keys differ from `en.json` (CI runs it).

## Adding a locale (for example `fr`)

1. Add `"fr"` to `LOCALES` in `src/lib/config/parse.ts`.
2. Add its native name to `LOCALE_NAMES` in `src/i18n/locales.ts`.
3. Copy `messages/en.json` to `messages/fr.json` and translate the values (keep keys).
4. Run `pnpm i18n:check`, then enable it with `VIETQR_LOCALES=vi,en,fr`.

## Theme

Light/dark toggle in the header. The choice is stored in `localStorage` (`theme`), falling
back to the system preference. An inline script in `<head>` (`theme-script.ts`) sets the
`dark` class on `<html>` before first paint, so there is no flash. Colours are CSS variables
in `globals.css` (`:root` and `.dark`).

## Accessibility checks

`pnpm test:e2e` runs Playwright specs in `e2e/` (axe, WCAG 2.2 AA, light and dark). First
time: `pnpm exec playwright install chromium`. Point at a running instance with `E2E_BASE_URL`.
